# v0.10 Phase A — Route coverage audit

**Status:** structural coverage tool implemented; broad live survey remains RPC-limited.

This audit answers **which supported routes we are structurally missing**, not whether any route is profitable.

## Usage

```powershell
cd C:\Users\YILDIZ\arb-radar
npm ci
npm run audit:coverage
```

Optional settings (PowerShell):

```powershell
$env:COVERAGE_LAUNCH_LIMIT="30"
$env:COVERAGE_DELAY_MS="1200"
$env:COVERAGE_RETRY_DELAY_MS="2500"
$env:ROBINHOOD_RPC_URL="YOUR_READ_ONLY_RPC_URL"
npm run audit:coverage
```

The script never signs, broadcasts, deploys or runs a transaction. The optional RPC value should be a standard read-only Robinhood Chain HTTP endpoint; no credentials are printed in the report.

## Classification

One result is emitted for each **directed** pair of markets from each successfully loaded typed Par multi-market launch.

- `hookless-all-v4`: at least one supported canonical all-V4 hookless closed cycle exists.
- `v4-hooks`: no hookless all-V4 route, but an all-V4 route with hooks exists.
- `mixed-v3-v4`: structurally closed route exists only with V3 reference hops.
- `no-closed-cycle`: the available metadata has no same-base closed route.
- `route-error`: metadata is internally inconsistent and route construction fails closed.

The classification tests common-prefix cancellation. A V3 hop appearing only in a **cancelled reference prefix** does not make the actual closed cycle mixed V3/V4.

When available, compression is measured against an actual original-reference-root cycle for the same market pair, not against an arbitrary longest route.

## Live observations and limits

On 2026-10-12, an initial bounded GitHub Actions run requested 30 launches:
- Par indexer returned **28 launches**.
- Only **3** had metadata successfully loaded.
- Those 3 contributed **46 directed pairs**, all classed as `mixed-v3-v4`.
- The other **25 launches** hit `HTTP 403` on public Robinhood RPC metadata calls.

This is **not** a valid 46/46 network-wide coverage ratio, because 25 launches were not classified.

A paced run requesting 12 launches still encountered public-RPC 403 responses. The audit now:
- paces requests and applies one bounded retry for 403/429/503,
- emits `completeness: incomplete-do-not-extrapolate` on missing metadata,
- returns non-zero on incomplete coverage,
- uses `set -o pipefail` in GitHub Actions so a failed Node audit cannot be hidden by `tee`,
- publishes the observed class breakdown and completeness in the Actions job summary.

The public CI smoke intentionally uses a **very small launch sample** to validate the integration without assuming the rate-limited endpoint can support a broader survey.

## Decision gate for Phase B

The observed small sample suggests V3 reference hops can be a material reason why otherwise closed market pairs are outside the current all-V4 truth engine.

**Do not implement a V3/V4 profit or atomic execution path solely from these partial observations.** Expand the sample through a reliable RPC and preserve separate checks for:
1. canonical state-accurate V3 exact-input quoting,
2. exact mixed-cycle amount parity,
3. atomic same-base profit-or-revert proof,
4. execution gas, Nitro parent/data fee and safety margin,
5. fail-closed green classification.

A structural mixed route is not an executable paper profit or a trading opportunity.
