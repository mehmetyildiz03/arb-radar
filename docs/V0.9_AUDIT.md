# v0.9 — State-Override Atomic Executor Audit

Date: 2026-10-02  
Issue: #30  
Status: paper-only research

## Objective

Replace the remaining V4Quoter execution-gas proxy with gas measured from the bytecode of a minimal atomic closed-cycle executor, without deploying the executor or submitting a transaction.

## Atomic executor

`contracts/AtomicCycleExecutor.sol` is deliberately narrow:
- hookless Uniswap v4 pools only,
- one exact-input closed cycle,
- same base asset at start and end,
- no wallet/account authorization,
- no token approvals,
- no persistent executor state,
- no deployment path in the application.

The executor hardcodes Robinhood's canonical V4 PoolManager:

`0x8366a39CC670B4001A1121B8f6a443A643e40951`

Within `unlockCallback` it:
1. validates PoolManager as caller,
2. reconstructs each sorted PoolKey,
3. performs exact-input swaps with canonical min/max sqrt-price limits,
4. rejects hooks and hook data,
5. checks delta signs,
6. rejects partial fills,
7. chains each realized output to the next hop,
8. requires the final currency to equal the starting base,
9. requires positive/minimum profit,
10. takes exactly the final base profit.

If the intermediate-delta netting assumption is wrong, PoolManager's own `CurrencyNotSettled` invariant reverts the unlock.

Pinned runtime:

## State-override simulation

`economic/atomicExecutor.ts` uses dummy address:

`0x000000000000000000000000000000000000A709`

The runtime bytecode is injected only for RPC simulation.

For a gross-positive V4Quoter quote:
1. `eth_call` is executed with the state override,
2. executor `amountOut` and `profit` are decoded,
3. output must exactly equal canonical V4Quoter output,
4. the identical transaction + override is sent to `eth_estimateGas`,
5. unsupported override gas estimation remains an explicit fallback rather than being synthesized.

No `eth_sendTransaction`, signer, private key or account is used.

## Cost calibration

Preferred v0.9 cost path:

`atomic executor estimateGas -> +20% buffer -> gas price -> Nitro parent/data fee -> 1% safety margin`

When atomic gas exists, Nitro child-gas overhead is **not added again**. Nitro is used for the parent/data component on the exact executor target and calldata.

Explicit modes:
- `atomic-override-nitro-calibrated`
- `atomic-override-parent-fallback`
- `quoter-proxy-nitro-calibrated`
- `legacy-fallback`

## Fail-closed green semantics

For v0.9, a positive numeric V4Quoter result is insufficient.

Green requires:
- supported hookless all-V4 closed cycle,
- canonical amount-sensitive V4Quoter quote,
- gross output > input,
- successful state-override atomic executor `eth_call`,
- atomic output exactly equals V4Quoter output,
- final paper net > 0 after the selected cost model,
- persisted `quote.green=true`.

The dashboard positive funnel checks this atomic-green evidence.

## Public RPC evidence

### Negative-path executor proof

A public Robinhood RPC live smoke successfully injected the executor runtime and called it on a real 3-hop ETH cycle.

Recorded sample:
- token: `0x88551234707f6dface9844339b08ca9b27306c1f`
- buy market: 0
- sell market: 1
- base: ETH
- block: `77698269`
- raw input: `100000000000000`
- V4Quoter output: `95447582447199`

Because output < input, the executor reverted with the expected:

`NoProfit(uint256,uint256)`

selector:

`0x31708d59`

This demonstrates that the injected runtime reached the profit-or-revert path on live chain state.

### State-override estimateGas support

The same public endpoint accepted a third state-override parameter for `eth_estimateGas` on an injected trivial runtime and returned:

**21,171 gas**

Therefore the public RPC supports the mechanism needed to measure the real executor transaction gas when a gross-positive cycle exists.

## Gross-positive capture status

A bounded multi-block capture workflow searches production Economic Truth marginal candidates and several cent-to-dollar exact sizes. It does not promote structurally arbitrary cycles to profitability candidates. If no gross-positive candidate is observed, a structurally supported negative cycle is used only to keep state-override integration coverage alive.

The final capture outcome for this branch is appended after the bounded workflow completes.

## Remaining boundaries

v0.9 still does **not** prove:
- transaction inclusion,
- realized profit,
- latency/capture success,
- profitability frequency,
- behavior of V3 or hooked routes,
- that a gross-positive opportunity will exist in every observation window.

The executor is simulation bytecode only and is never deployed or funded by Arb Radar.
