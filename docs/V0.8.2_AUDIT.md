# v0.8.2 — Executable Depth Audit

Date: 2026-09-27  
Issue: #22  
Status: paper-only research

## Why this audit was required

v0.8/v0.8.1 correctly separated same-block marginal state from exact closed-cycle quoting, but the live dashboard showed a recurring pattern:

- very large positive marginal edge,
- few exact quotes,
- no verified positive paper result,
- candidates often stopping after one quote.

The open question was whether the fixed minimum notional was hiding profitable sub-dollar depth, or whether the apparent opportunity existed only at microscopic / non-scalable liquidity.

## Full live depth sweep

A public read-only diagnostic was run against Robinhood mainnet using canonical StateView + V4Quoter. The tested USD inputs were:

`$0.01 / $0.03 / $0.10 / $0.30 / $1 / $3 / $10`

The research cost model was unchanged:
- canonical V4Quoter amount output,
- V4Quoter gas estimate + 20% research buffer,
- current gas price,
- $0.05 explicit extra allowance,
- 1% output safety margin.

## Root cause of quoteCount=1 / quote failures

The common outer revert was:

`UnexpectedRevertBytes(bytes)`

The nested selector decoded to:

`NotEnoughLiquidity(bytes32 poolId)`

from the canonical Uniswap v4 Quoter path.

This is economically meaningful. It means the requested exact input could not be fully consumed along the closed cycle before the pool's available swap path was exhausted. It is not treated as a zero-P&L quote and is not silently ignored.

## v0.8.2 production response

### 1. One-cent first probe

`MIN_CANDIDATE_TRADE_USD` defaults to **$0.01**.

This preserves the successful cent-scale quote that v0.8.1's $0.10 gate would have missed.

### 2. Depth-aware exact ladder

Sizing now uses an ascending fixed-block depth ladder:

`0.01 -> 0.03 -> 0.10 -> 0.30 -> 1 -> 3 -> 10 -> 30 -> 100 USD`

The ladder is clipped by:
- configured minimum,
- paper capital,
- max candidate trade.

### 3. NotEnoughLiquidity is a depth boundary

When canonical V4Quoter returns `NotEnoughLiquidity(poolId)`:

- the failure is recorded with input size and pool id,
- the smaller successful quote remains valid research evidence,
- larger ladder amounts are not attempted,
- analytical seed refinement may only inspect untried sizes below that observed boundary.

Unknown revert/RPC failures still fail closed.

### 4. Gross-negative early stop

If an exact successful quote already has `output <= input`, larger sizes are not attempted. For the same hookless directed V4 cycle, increasing exact input cannot improve its average execution price.

This stop now also prevents analytical seed extras from running after a gross-negative result.

### 5. Best-size opportunity accounting

The runtime opportunity counter now accepts a verified positive best sizing quote, not only a positive first probe.

The dashboard's green criterion itself is unchanged:
- same-base closed cycle,
- canonical exact quote,
- `verifiedClosedCycle=true`,
- net >= configured minimum after all research costs.

### 6. Dashboard depth telemetry

Capture Quality now exposes:
- **Depth reject** — unique candidates with an exact depth failure,
- **NotEnoughLiquidity** — total decoded liquidity-boundary events.

This explains why marginal candidate count can greatly exceed exact quoted candidates.

## Validation

The v0.8.2 branch adds tests for:

- the exact depth ladder,
- keeping a smaller successful quote when the next size hits `NotEnoughLiquidity`,
- fail-closed behavior for unknown quote errors,
- gross-negative early stop,
- no analytical seed calls after gross-negative stop,
- preserving an observed liquidity boundary after a smaller seed refinement,
- dashboard unique depth-reject count vs raw failure-event count.

The full CI matrix, dashboard smoke, deterministic LONG5 replay, strict public live smoke and final truth diagnostic must be green before merge.

## Interpretation

The audit changes the meaning of the earlier giant marginal percentages:

**Marginal edge is a direction/depth-discovery signal, not executable capacity.**

A pool can have a very favorable infinitesimal price while supporting only cents — or less — of exact closed-cycle input. v0.8.2 therefore treats canonical exact depth as a first-class property rather than forcing every candidate through a large fixed sizing grid.

No cost was removed to create green results. No observed sample in this audit was paper-positive.
